# 武器交互与携行系统设计

> 状态：概念设计 / 尚未实现
>
> 讨论日期：2026-08-05
>
> 关联模块：背包与携行、弹药、换弹、战术配件、第一人称身体可视化

## 1. 设计目标

本系统希望保留战术选择和身体沉浸感，同时避免让玩家把大量时间消耗在传统格子背包的排列整理上。

核心原则：

1. **不采用“华容道”式格子背包。** 不以旋转物品、拼格子和反复整理空间作为主要玩法。
2. **重要交互尽量发生在角色身体和武器上。** 玩家能看见自己的身体，因此胸挂、腰带和装备上的物品应成为可理解、可交互的实体。
3. **简单操作提供智能默认行为，复杂选择按需展开。** 短按完成常用动作，长按才打开选择界面。
4. **细节投入优先服务枪械原理和物理模拟。** 操作复杂度本身不是目标，不应为了“真实”而故意刁难玩家。
5. **输入方案保持一致。** 换弹和战术配件都采用“短按默认操作、长按呼出轮盘”的统一逻辑。

## 2. 携行系统定位

### 2.1 不做什么

- 不做以二维格子面积为核心的背包整理。
- 不要求玩家为每次换弹打开背包界面。
- 不让弹匣只表现为一个抽象的总弹药数字。
- 不把大量专用快捷键作为完成基础操作的前提。

### 2.2 建议的数据模型

玩家携带的战斗物资按**身体槽位和容器**组织，而不是按自由拼接的二维格子组织。

```text
PlayerLoadout
├── ChestRig
│   ├── MagazinePouch 1 → MagazineInstance
│   ├── MagazinePouch 2 → MagazineInstance
│   ├── MagazinePouch 3 → MagazineInstance
│   └── UtilityPouch    → ItemStack / MedicalItem
├── Belt
│   ├── MagazinePouch
│   ├── GrenadePouch
│   └── MedicalPouch
└── Backpack
    └── 容量/分类式储存，不参与即时换弹选择
```

每个弹匣应是独立实例，至少记录：

| 字段 | 说明 |
|------|------|
| `magazine_id` | 唯一标识 |
| `compatible_weapon_tags` | 可兼容的武器或口径 |
| `capacity` | 弹匣容量 |
| `rounds` | 当前剩余弹数或弹药序列 |
| `ammo_type` | 弹种；若支持混装则改为逐发序列 |
| `condition` | 弹匣状态/耐久，预留给故障系统 |
| `pouch_slot` | 当前所在身体槽位 |

背包用于携带补给和非紧急物品；胸挂、腰带等快速取用槽位才参与战斗中的选弹匣、医疗和投掷物操作。

## 3. 换弹交互

### 3.1 短按 R：默认换弹

短按 `R` 执行快速、低认知负担的默认换弹：

1. 从可用快速取用槽位中选择下一个兼容弹匣。
2. 默认按稳定顺序选择，例如胸挂从左到右，再到腰带。
3. 跳过空弹匣和不兼容弹匣。
4. 若当前弹匣仍有弹，按战术换弹流程处理；若已打空，按空仓换弹流程处理。
5. 换下的弹匣优先放回它原本对应的快捷槽位。

短按操作不应随机选择弹匣。稳定顺序更可预测，也方便玩家通过身体槽位形成肌肉记忆。

背包中的弹匣不直接参与换弹。玩家必须先把弹匣移动到胸挂、腰带等快捷槽位，才能通过短按、轮盘或身体注视选择它。

### 3.2 快速双击 R：紧急换弹

快速双击 `R` 执行紧急换弹：

1. 直接丢弃当前枪内弹匣，不执行放回原槽位的动作。
2. 按既定槽位顺序选择下一个兼容弹匣。
3. 使用更短的换弹动作和时长，体现省略收纳步骤带来的速度优势。
4. 被丢弃的弹匣作为世界物品落地，保留内部剩余弹药；是否允许重新拾取由掉落物系统处理。

紧急换弹的代价是失去对当前弹匣的即时控制。在弹药仍然充足时误用，可能损失非空弹匣或迫使玩家之后返回拾取。

### 3.3 长按 R：弹匣轮盘

长按 `R` 达到阈值后呼出弹匣选择轮盘：

- 每个扇区对应一个可用弹匣。
- 显示槽位、弹匣类型和大致剩余弹量，不显示精确弹数。
- 松开 `R` 或确认输入后，使用当前选中的弹匣换弹。
- 取消时不触发换弹。
- 不兼容、空弹匣或不可触及的槽位显示为禁用状态。

建议长按阈值为 `0.25–0.35s`。轮盘打开后游戏保持正常时间流速，单人和联机采用一致规则。

### 3.4 低头看身体：空间化选弹匣

当玩家低头并看见胸挂时，可以直接瞄准身体上的弹匣槽位进行选择：

1. 摄像机视线或屏幕中心射线命中 `MagazinePouchInteractable`。
2. 命中的弹匣获得轻量高亮或轮廓提示。
3. 按下换弹键后，优先使用被注视的弹匣。
4. 没有有效注视目标时，回退到短按 `R` 的默认顺序。

该方案让身体可视化直接参与玩法，但不应成为换弹的强制前置步骤。玩家在紧急情况下仍可只按一次 `R`。

### 3.5 输入优先级

```text
按下 R
├── 在双击窗口内第二次按下
│   └── 紧急换弹 → 丢弃当前弹匣并按槽位顺序选择新弹匣
├── 松开时间 < 长按阈值，且双击窗口结束
│   ├── 正注视有效弹匣 → 使用被注视弹匣，旧弹匣放回原槽
│   └── 无有效目标     → 按默认顺序选择，旧弹匣放回原槽
└── 持续按住 ≥ 长按阈值
    └── 打开弹匣轮盘 → 选择 / 取消
```

一旦轮盘已经打开，松开 `R` 不得再额外触发一次默认换弹。

由于单击和双击共用 `R`，输入控制器需要一个短暂的双击判定窗口。建议默认值为 `0.20–0.25s`，并通过实机手感测试，在响应速度和误触率之间调整。

## 4. 弹匣与现有换弹系统的连接

目前 `AmmoComponent` 使用弹匣数组和 `current_magazine` 管理弹药。后续接入携行系统时，应逐步把数组元素提升为独立的 `MagazineInstance`，同时保留以下职责边界：

| 模块 | 职责 |
|------|------|
| `Loadout/InventoryComponent` | 管理身体槽位、背包和物品归属 |
| `MagazineInstance` | 保存单个弹匣的容量、余弹、弹种和状态 |
| `AmmoComponent` | 管理枪内弹匣、膛内弹和供弹状态 |
| `BaseWeapon` | 执行战术/空仓/分段换弹流程 |
| `ReloadSelectionController` | 处理单击、双击、长按、注视选择和候选弹匣 |
| `MagazineWheelUI` | 展示候选弹匣并返回玩家选择 |
| `BodyPouchInteractable` | 提供身体可视化槽位的射线命中与高亮 |

建议换弹接口最终演进为：

```gdscript
weapon_manager.request_reload(selected_magazine_id := "")
weapon_manager.request_emergency_reload()
```

- 参数为空：由选择控制器按注视目标或默认顺序选择。
- 参数非空：使用轮盘或身体交互明确选中的弹匣。
- `BaseWeapon` 不直接搜索背包，只接收已经验证可用的弹匣实例。
- 紧急换弹接口会先把枪内弹匣移交给世界掉落物系统，再开始精简后的换弹阶段。

## 5. 战术配件交互

战术配件沿用与换弹一致的输入范式。

### 5.1 短按 T

执行当前武器的默认战术配件操作，例如切换主照明设备。具体默认项由武器配置或最近一次选择决定。

### 5.2 长按 T

呼出战术配件轮盘，可选择并开关：

- 战术灯
- 激光指示器
- 红外照明/红外激光
- 可切换倍率或其他支持开关的配件

轮盘只展示当前武器实际安装、可操作的配件，不显示空槽位。

### 5.3 单武器专属快捷键

改枪界面可以允许玩家为某个战术配件绑定专属快捷键。运行时绑定属于**唯一武器实例**，而不是玩家的全局同类配件设置；武器预设只能提供首次生成时使用的出厂默认值。

设计意图：

- 同一把武器无论由谁拾取，都保留原有控制布局。
- 玩家拿到他人的武器时可能需要短暂适应其配件控制方式。
- 该机制只提供进阶便利，不能取代短按/长按 `T` 的通用操作。

每把武器实例**最多只能绑定一个专属按键**，且这一个按键只控制一个已安装战术配件的一个操作。创建新绑定会明确提示并覆盖该武器原有绑定。长按 `T` 的轮盘始终保留，作为其他配件和未绑定操作的通用入口。

#### 存档方案比较

| 方案 | 保存位置 | 优点 | 问题 | 结论 |
|------|----------|------|------|------|
| 全局玩家键位 | `user://keybinds.cfg` 或玩家设置 | 实现简单，可复用现有 `KeybindStore` 编码方式 | 绑定跟玩家而不是跟枪，别人拾取武器后不会继承原控制 | 不采用 |
| 武器资源配置 | `WeaponConfig.tres` / 配件资源 | 出厂默认值直观，适合开发期预设 | 资源被同类武器共享，运行时修改会污染所有实例，也不适合作为玩家存档 | 只允许保存出厂默认值 |
| 武器实例状态 | 角色、仓库或世界存档中的 `WeaponInstanceData` | 绑定跟随唯一武器实例，掉落、拾取和转移所有权后仍保留 | 需要武器唯一 ID 和实例序列化 | **采用** |

推荐使用以下实例数据：

```gdscript
class_name WeaponInstanceData

var instance_id: String
var weapon_config_id: String
var custom_binding := {
	"event": {},              # 编码后的单个键盘/鼠标事件
	"attachment_slot": "",  # 目标配件所在稳定槽位
	"attachment_id": "",    # 目标配件实例 ID，用于二次校验
	"operation": "toggle",   # 首期仅支持 toggle
}
```

存档规则：

- `WeaponConfig` 可以提供出厂默认绑定，但玩家在改枪界面设置后写入 `WeaponInstanceData`。
- 玩家持有时，绑定随角色/仓库存档保存；掉落后，绑定随世界武器实体保存。
- 联机由服务器保存并校验绑定，客户端只负责输入和 UI 展示。
- 只序列化一个输入事件，不创建“每把枪一个 InputMap action”。输入控制器读取当前武器的单条绑定并与输入事件匹配。
- 输入事件编码格式可以复用现有 `KeybindStore` 的字典结构，但应使用独立的武器实例存档文件或存档段，不能混入全局 `keybinds.cfg`。
- 目标配件被拆除后保留绑定记录但标记为失效；重新装回同一实例可恢复。给其他配件绑定时直接覆盖旧记录。
- 与移动、开火、换弹、暂停等核心键冲突时禁止保存；与非核心操作冲突时显示警告，并要求玩家确认覆盖或取消。

## 6. UI 与反馈要求

### 6.1 弹匣轮盘

- 扇区数量随可用弹匣动态变化，但应设置可读性上限。
- 使用统一图标表示胸挂、腰带等槽位来源。
- 当前枪内弹匣与候选弹匣必须在视觉上区分。
- 弹量只按上次检查得到的百分比区间显示，不提供精确弹数。
- 未检查过或检查结果已经失效的弹匣显示为“未知”。
- 选中后应立即关闭轮盘，并接入现有换弹圆形倒计时。

### 6.2 身体交互

- 高亮必须克制，不能持续遮挡身体模型。
- 只有进入可交互视角范围后才显示提示。
- 无效弹匣应提供明确但简短的原因，例如“不兼容”或“空弹匣”。

### 6.3 弹匣检查与模糊弹量

玩家必须把弹匣从武器或快捷槽位中拔出并执行检查，才能获得其大致剩余弹量。系统按 `当前弹数 / 弹匣容量` 计算百分比，再映射为文字状态：

| 百分比 | 显示 |
|--------|------|
| `90%–100%` | 满 |
| `60%–89%` | 较多 |
| `30%–59%` | 较少 |
| `1%–29%` | 近空 |
| `0%` | 空 |

这些阈值是首版建议值，可以在手感测试后调整。UI 保存的是玩家角色对该弹匣的**最近一次检查结果**，不是实时透视数据：

- 检查后，轮盘和身体槽位提示可以显示对应档位。
- 弹匣在枪内继续射击后，旧检查结果应标记为失效或“未知”，不能继续显示过时档位。
- 补弹、混装弹药或由其他角色操作后，也应使旧检查结果失效。
- 服务器保存真实弹数；模糊显示和检查记录属于玩家可知信息层。

### 6.4 输入提示

首次触发相关条件时提示：

- `按 R：快速换弹`
- `快速双击 R：丢弃弹匣并紧急换弹`
- `长按 R：选择弹匣`
- `低头注视胸挂弹匣后按 R：指定弹匣`
- `拔下弹匣检查：获取大致余弹`
- `长按 T：管理战术配件`

## 7. 边界情况

- **没有兼容弹匣：** 不进入换弹流程，给出声音和 UI 反馈。
- **选择期间受击、冲刺或切枪：** 关闭轮盘；是否中断已经开始的换弹由现有分段换弹规则决定。
- **弹匣在动作开始后失效：** 开始动画前再次验证归属和兼容性。
- **轮盘候选过多：** 优先展示快速取用槽位，背包弹匣不直接进入战斗轮盘。
- **原槽位不可用：** 普通换弹不能静默吞掉旧弹匣；应尝试其他兼容空槽位，仍无位置时提示玩家改用紧急换弹或取消动作。
- **紧急换弹掉落失败：** 未成功生成或移交世界掉落物前，不得从枪内删除弹匣数据。
- **双手被占用或姿态受限：** 禁止对应交互，并给出原因。
- **联机同步：** 服务器校验弹匣归属、余弹和换弹结果；客户端只做选择与表现预测。

## 8. 建议实施阶段

### P1：数据与默认换弹

- 引入独立 `MagazineInstance`。
- 在弹匣实例和玩家可知信息层中预留“上次检查档位/是否失效”数据。
- 建立胸挂/腰带快速取用槽位。
- 将现有 `AmmoComponent` 与携行弹匣实例连接。
- 短按 `R` 按固定顺序选择兼容弹匣。
- 普通换弹将旧弹匣放回原槽位。
- 背包弹匣必须先移动到快捷槽位。

### P2：弹匣轮盘

- 区分短按和长按 `R`。
- 识别快速双击 `R`，实现丢弃弹匣的紧急换弹。
- 实现 `ReloadSelectionController`。
- 实现 `MagazineWheelUI`。
- 实现拔匣检查动作和百分比档位显示。
- 接入当前换弹状态、倒计时和中断逻辑。

### P3：身体可视化选择

- 在胸挂模型上布置可交互槽位。
- 实现视线检测、高亮和指定弹匣选择。
- 首期手部 IK 只覆盖胸挂槽位。
- 腰带和其他身体部位需要独立取用动画，不纳入首期通用 IK。
- 增加第三人称/联机状态同步。

### P4：战术配件轮盘与快捷键

- 短按/长按 `T` 输入状态机。
- 动态读取武器已安装的可操作配件。
- 保存单武器快捷键绑定。
- 补充拾取他人武器后的控制提示。

## 9. 设计决策记录

### 9.1 已确认

| 编号 | 议题 | 决策 |
|------|------|------|
| D1 | 短按 `R` 如何选择弹匣 | 严格按照身体槽位的既定顺序选择，不按余弹量排序，也不随机选择。 |
| D2 | 是否显示精确余弹 | 不显示精确数字。玩家拔下弹匣检查后，系统按剩余百分比显示“满 / 较多 / 较少 / 近空 / 空”；未检查或结果失效时显示“未知”。 |
| D3 | 战术换下的弹匣如何处理 | 普通换弹优先放回原槽位；不采用弹匣回收袋作为默认机制。快速双击 `R` 时直接丢弃当前弹匣，执行紧急换弹。 |
| D4 | 背包弹匣能否直接换上 | 不能。背包中的弹匣必须先移动到胸挂、腰带等快捷槽位，才能参与战斗换弹。 |
| D5 | 打开轮盘是否减慢时间 | 不减慢时间。轮盘是实时战斗交互，单人和联机保持一致。视觉表现可以参考实时武器轮盘，但不复制时间减速机制。 |
| D6 | 身体槽位是否配合手部 IK | 首期手部 IK 只覆盖胸挂。腰带和其他部位需要制作新的专用取用动画，后续按资源和实现难度扩展。 |
| D7 | 单武器快捷键如何保存 | 每把武器实例只能保存一个专属按键绑定。绑定写入 `WeaponInstanceData` 并随武器流转；全局键位文件不保存该绑定，`WeaponConfig` 只可提供出厂默认值。 |

### 9.2 其他待确认项

- 双击 `R` 的判定窗口，以及是否允许玩家在设置中调整。
- 紧急换弹相比普通换弹具体缩短哪些动画阶段、缩短多少时间。
