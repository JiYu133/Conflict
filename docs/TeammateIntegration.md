# 队友代码集成说明

本次以当前项目为基础，集成 `classes/player/队友改动/` 中的有效代码快照。队友快照基于较早版本，因此按功能合并，保留当前项目后续完成的移动、独立武器表现、瞄准、屏息和瞄具设置。

## 目录归属

| 目录 | 职责 |
|---|---|
| `classes/player/` | `BasePlayer` 组合根、AI 入口、模型管理及战斗通知桥 |
| `classes/player/config/` | 玩家、移动、相机、瞄准、模型查找、布娃娃、脊柱瞄准和体力配置 |
| `classes/player/controller/` | 移动、相机、视线、动画、姿态、转身、碰撞、音频、瞄具渲染、武器表现和屏息控制器 |
| `classes/player/system/` | 控制权、体力、布娃娃、武器掉落、武器反馈和屏幕效果 |
| `classes/services/` | 应用管理、日志接口与实现、设置、键位存储和设置文案 |
| `classes/ui/` | 界面及玩家 UI 装配层 `PlayerUILayer` |

`force/`、`ik/`、`medical/` 保持各自模块边界。迁移后的 `.tres`、Autoload、preload 和文档路径已同步更新；已有脚本的 `.uid` 随文件迁移。`GlobalLogger` 改用明确脚本路径注册，避免首次导入依赖本机 UID 缓存。

## 组件装配

`BasePlayer` 按以下阶段装配子系统，并对必需依赖增加调试断言：

1. `_create_core_subsystems()`：创建核心组件。
2. `_initialize_controllers()`：注入配置、状态提供者及控制器依赖。
3. `_initialize_combat_feedback()`：初始化碰撞、医疗表现、体力、音频和武器反馈。
4. `_create_ui_subsystems()`：仅为本地玩家创建医疗操作、屏幕效果和 UI 层。
5. `_connect_signals()`：连接模型、武器、姿态、医疗及运动事件。

模型加载回调与输入处理也按职责拆成较小的方法，保留现有执行顺序及当前版本的武器表现接口。

`PlayerUILayer` 通过 `initialize()` 显式接收玩家、设置服务、武器管理器和医疗操作组件，自行创建 HUD、菜单、控制台和轮盘。`BasePlayer` 保留菜单引用，供已有调用方使用；`MedicalTreatment` 仍直接挂在玩家下，兼容遭遇战节点路径。

UI 层退出时只清理仍归属自己玩家的轮盘注册，释放全局服务保存的回调，避免场景切换时访问旧组件或误清理新玩家的轮盘。

`PlayerWeaponFeedback` 显式接收受力、IK、相机、体力和武器管理器，负责后坐力接触分配、换枪绑定及携行重量同步。玩家的布娃娃状态守卫仍留在 `BasePlayer.apply_weapon_recoil()`；当前独立武器表现控制器和屏息组件继续使用原有接线。

## 冲突处理

- 只采用有效快照；`_stale/` 中已撤回的改动不纳入。
- 保留当前相机、IK、脊柱和动画逻辑，未采用快照中的旧版回退。
- 设置服务从当前文件迁移，保留新增瞄具选项、当前键位和设置数据格式。
- 控制台采用命令处理表，保留现有命令实现；状态查询兼容没有活动 `AnimationPlayer` 片段的玩家。
- 日志默认继续使用 `GlobalLogger`，相关组件可注入其他 `LoggerService` 实现。
- 队友原始文件夹完整保留，并增加 `.gdignore`，避免其中的同名脚本参与 Godot 扫描。
- 保留原工作区已有的美术资源及武器功能改动；资源文件中与本次迁移有关的修改仅更新脚本路径。

## 回归入口

`tools/check.ps1` 已合入：捕获标准输出、错误输出和退出码，同时检查运行器完成报告；支持 `-GodotPath`、`GODOT_PATH` 和 `-Quick`，日志保存在 `.appdata/regression/`。项目中已补齐相应场景运行器，并保留现有瞄准及屏息回归。

按本次集成时用户的最新要求，停止继续执行测试；最后的代码修正未重新运行完整回归。
